Generated by the agents that wrote and checked `csat/`. For the expert review: check the questions first, then spot-check the claims marked `fixed` or `unverifiable`.

**Claims checked against the code:** fixed 44, removed 4, unverifiable 1, verified 141.

## 0. Added after the agents (main session, from the board diagnosis)

- system.md, Coherence unit: added "An ID remapper between the CCU and the crossbar holds 4 IDs with one transaction
  each per direction: at most 4 reads and 4 writes from all CCU ports together are in flight to the LLC."
  Evidence: `hardware/include/ariane_soc_pkg.sv` RemapMaxUniqIds = 4, RemapTxnsPerId = 1;
  `hardware/host/cva6_axi_id_remap.sv:253` (a read is accepted only if its ID has room or the table is not full).
  The fact is from the RTL. Whether this limit explains the board result of 2026-11-23 (a best-effort reader losing
  bandwidth next to hard-limited readers) is NOT established: the first simulation (t_bchol) showed no read waiting
  for an ID with 1 to 3 parked aggressors. Under investigation; do not read the bullet as a diagnosed bottleneck.

- 2026-11-23, RTL changes after the agents (main session), docs updated with them:
  - CVA6: `stvec` reads back as stored outside CLIC mode (`csr_regfile.sv`); the unused CVXIF port is off in the
    configuration (`CVA6ConfigCvxifEn = 0`), so an undecoded instruction raises an illegal-instruction exception
    in the decoder instead of hanging the hart in the issue stage. This answers the cores question below about
    CVXIF. blocks/cores.md Properties, test `t_trap`.
  - Bandwidth controller: a reservation is earned at a constant rate over the period (`axi_llc_cbqri_bc.sv`);
    LLC lookup: exact lock table in place of the Bloom filter (`axi_llc_lock_box_exact.sv`). blocks/qos.md,
    blocks/llc.md, hardware/docs/qos.md, test `t_bchol`; system.md test count 31 -> 33.
  - 2026-11-24: the token bucket keeps one line for the reserved classes, and a release takes two cycles (the
    choice is registered, then released); the release decision as one path was the SoC's slowest at 50 MHz and
    builds missed timing on it. blocks/qos.md, hardware/docs/qos.md. Bitstream `qosfix4_4c` (setup +0.364 ns):
    board suite 11 of 12 (`t_part`'s noise check, as before), `t_trap`, `t_bchol`, `t_bc`, `t_bcw`, `t_bcd`,
    `t_qosv` pass; Linux 7.2 with the kernel payload of 2026-11-18 (no workaround) takes a forbidden `rdcycle`,
    an undefined opcode and a null load as signals.
  - 2026-11-24, loader: `QOS_FIRMWARE` (M mode gets IDs of its own). Board measurements and JTAG samples showed
    that the reader's remaining loss next to cores limited to `MB_MIN` 1 was OpenSBI being throttled under the
    limited task's IDs. blocks/boot.md, blocks/qos.md, hardware/docs/qos.md. `netboot_qos_fw.riscv` is the build
    with `QOS_KERNEL=0x80008 QOS_USER=0x10001 QOS_FIRMWARE=0x80008`.
