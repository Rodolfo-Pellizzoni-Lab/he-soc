# DRAM path

Main memory and everything between the LLC's memory port and it. On the VCU118 that is DDR4 behind the Xilinx MIG,
with OpenDRAM as an optional replacement for the MIG's controller. In xsim it is a behavioural AXI memory. Two timing
stages sit in front of the memory and can make it look slower: a fixed slowdown regulator and a programmable
FASED-style DRAM timing model, so memory-contention behaviour can be studied for slower or faster targets.

## How it works

**Chain** (`host_domain.sv`). LLC memory port → `i_spu_llc_mem` (the APMU's snooper on the memory port; it only
watches) → `slowdown_mem_top` → `axi_dram_timing` → `mem_axi_bus` → the memory of the build target. The bus is
64-bit AXI with the LLC memory port's ID, one bit wider than the crossbar's slave-side ID (`IdWidthSlave + 1`). The
`user` field carries the QoS tag and CCU source of the request that caused each refill or eviction.

**Slowdown regulator** (`ip_list/slowdown`). It queues requests and releases at most one address per fixed number of
cycles, and it delays every R and B response by a fixed number of cycles. Its parameters are set at its instance in
`host_domain.sv`, and it has no registers.

**DRAM timing model** (`host/axi_dram_timing.sv`). It reads the SoC clock as the clock of the emulated target.
Requests go to the real memory at once. The model holds each response until the target DRAM would have delivered it:

- a read burst starts `LAT_RD` cycles after the accepted AR, a write burst `LAT_WR` cycles after the AW, each no
  earlier than the modelled data bus is free;
- the bus, shared by reads and writes, costs `OCC16`/16 cycles per 8-byte beat; the write response comes at the end
  of the burst's bus time.

Its time base counts 1/16 cycles in 64 bits. It tracks up to 16 read bursts and 8 write bursts and buffers up to
32 read beats. It assumes in-order responses and reports an out-of-order ID in simulation. When disabled, it is a
wire once its buffers drain. Counters: bursts accepted, late reads and their lateness, hold cycles, read beats. Every
SoC reset clears it and disables it, including the debug module's ndmreset.

**FPGA memory** (Bender target `ddr`, define `XILINX_DDR`; `fpga/ddr/alsaqr_xilinx.sv`). `mem_axi_bus` leaves the
SoC as `axi_ddr_master` and crosses into the MIG's UI clock through an `axi_cdc`. It then enters the AXI slave of
`ddr4_0`:

- one x16 DDR4 component (MT40A256M16GE-083E), 16-bit DQ, tCK 1600 ps (DDR4-1250), CL 9;
- 64-bit AXI, 29-bit address: 512 MB at the SoC's DRAM window;
- address order `ROW_COLUMN_BANK`.

The IP is generated by `fpga/alsaqr/tcl/ips/ddr/run.tcl`, with its AXI ID width taken from `AXI_ID_DDR_WIDTH`
(`fpga/setup.sh`).

**OpenDRAM** (`ip_list/opendram`). With `OPENDRAM=1`, `fpga/run.tcl` sources `opendram.tcl`. That script generates
the MIG in the project with auto-precharge off and patches it so that `opendram_mc` replaces the MIG's memory
controller. The MIG keeps its PHY, calibration, refresh and AXI front end. The RTL copy here has every DRAM timing
constraint scaled by 16 (`rtl/command_scheduler/time_constraints.vh`), which makes row misses expensive.

**Simulation memory** (`XSIM_SIM_DRAM`, set by `hardware/xsim/env.sh`). An `axi_sim_mem` sits behind an `axi_cdc`
into a separate faster clock and an `axi_delayer` with random stalls on every channel. This models the
clock crossing and variable latency of the board. `XSIM_DRAM_IDEAL` connects the memory directly in the SoC clock.

## Configuration

- `USE_SLOWDOWN`: a `define` at the top of `host_domain.sv`. Without it, the SPU feeds the timing model directly.
- `OPENDRAM=1` (FPGA build environment, `fpga_build` config): OpenDRAM in place of the MIG controller.
- Bender target `ddr` / `XILINX_DDR`: DDR4 through the MIG. Without it, the FPGA DRAM window shrinks
  (`HYPER_FPGA_DDR` in `ariane_soc_pkg.sv`) and `mem_axi_bus` goes to the HyperBus subsystem.
- `XSIM_SIM_DRAM`, `XSIM_DRAM_IDEAL`: simulation memory and its ideal variant.
- `EXCLUDE_LLC` (`exclude-llc=1`): the crossbar's DRAM route goes straight to the memory, without LLC, slowdown or
  timing model.
- `L3_TCSRAM` (`l3-fake=1`): an on-chip SRAM (`l3_onchip_subsystem`) answers the crossbar's DRAM route instead.
- Model table sizes: `axi_dram_timing` parameters `RdDepth`, `WrDepth`, `RBufDepth`, `BBufDepth`.

## Using it

- The timing model's configuration (`CTRL` enable/clear, `LAT_RD`, `LAT_WR`, `OCC16`), counters and presence ID
  register sit in the SoC control register block. `apb_soc_control.sv` routes a sub-range to the model; the fields
  are `dram_model_pkg::cfg_t` / `cnt_t`.
- `soc_lookup` (alsaqr-mcp) returns the addresses. Bare-metal code programs them as in `software/soc_tests/t_dram`.
  Under Linux, `devmem` does the same.

## Verification

- `t_dram` (`sim_regress` suite `soc`, and on the board): real dependent-read latency, fixed latency, late detection,
  bandwidth limit on chase and stream, writes, pass-through when disabled.
- `t_sweep` (cycles per dependent read against array size, model off and at 1 GHz values; `plot_sweep.py` draws
  it), `t_sweep_probe`: run by name.
- `t_bc` uses the model to make memory the bottleneck.
- `hardware/xsim/tests/run_dm_wrap.sh` (`tb_dm_wrap.sv`): the time base across 2^48 sixteenths.
- Slowdown: `ip_list/slowdown/test/tb_slowdown.sv`; software `slowdown_bw`, `slowdown_qc`, `slowdown_st`.
- OpenDRAM: `ip_list/opendram/sim/` (a recipe that runs OpenDRAM's own testbench with this MIG configuration).

## Properties

- The model can only delay. A setting emulates its target only when the real memory answers sooner than the model.
  Otherwise the beat leaves one cycle after it arrives and the read counts as late. The SoC clock is not gated.
- While enabled, the model keeps every beat in its buffer for at least one cycle.
- OpenDRAM keeps a row open after a read, so its latency depends on the row (most at 16x timing).
- Every LLC line refill is an 8-beat burst. The LLC answers the core only after the last beat.
- The SPU on the memory port sees requests before the slowdown and responses after both timing stages.
